---
title: Other Providers
description: Add OpenRouter, Anthropic, OpenAI-compatible, or local providers.
---

Use the same nested `providers.json` provider/model catalog for any compatible
provider. The TOML snippets below are legacy equivalents kept for migration;
new configuration should use the JSON shape from [Provider Setup](./provider-setup).

The exact base URL and model names come from the provider you choose. Devo
needs the provider endpoint, a credential reference when authentication is
required, the supported wire API, and a nested model record keyed by the
provider model name.

## Anthropic

```json
{
  "model": "anthropic/claude-sonnet",
  "provider": {
    "anthropic": {
      "name": "Anthropic",
      "base_url": "https://api.anthropic.com",
      "credential": "anthropic_api_key",
      "wire_api": "anthropic_messages",
      "models": {
        "claude-sonnet": {
          "name": "Claude Sonnet",
          "context_window": 200000,
          "input_modalities": ["text", "image"]
        }
      }
    }
  }
}
```

The nested model key is the provider-facing model id; there is no separate
binding to create.

## OpenAI Responses-Compatible

```json
{
  "model": "openai/gpt-5",
  "provider": {
    "openai": {
      "name": "OpenAI",
      "base_url": "https://api.openai.com",
      "credential": "openai_api_key",
      "wire_api": "openai_responses",
      "models": {
        "gpt-5": {"name": "GPT-5"}
      }
    }
  }
}
```

Use the Responses wire API when the provider endpoint supports it and the model
behavior you need depends on Responses features.

## OpenAI Chat Completions-Compatible

```json
{
  "model": "gateway/custom-main",
  "provider": {
    "gateway": {
      "name": "OpenAI-compatible Gateway",
      "base_url": "https://gateway.example.com/v1",
      "credential": "gateway_api_key",
      "wire_api": "openai_chat_completions",
      "models": {
        "custom-main": {
          "name": "Gateway Main",
          "options": {"enable_reasoning": true},
          "request": {"vendor_parameter": "value"},
          "headers": {"X-Workspace": "team-a"}
        }
      }
    }
  }
}
```

This pattern covers many gateways and local proxies.

## OpenRouter-Style Gateway

OpenRouter-like providers often use provider-qualified model names:

```json
{
  "model": "openrouter/moonshotai/kimi-k3",
  "provider": {
    "openrouter": {
      "name": "OpenRouter",
      "base_url": "https://openrouter.ai/api/v1",
      "credential": "openrouter_api_key",
      "wire_api": "openai_chat_completions",
      "models": {
        "moonshotai/kimi-k3": {"name": "Kimi K3"}
      }
    }
  }
}
```

Keep the complete provider-facing id as the nested model key.

## Local Provider Or Proxy

For a local OpenAI-compatible server:

```json
{
  "model": "local/local-main",
  "provider": {
    "local": {
      "name": "Local Provider",
      "base_url": "http://127.0.0.1:11434/v1",
      "wire_api": "openai_chat_completions",
      "models": {
        "local-main": {"name": "Local Main"}
      }
    }
  }
}
```

If the local provider does not require an API key, omit `credential`. If it does,
set `credential` to an id in the user-scoped `auth.json`; never put the key in
`providers.json`.

For a provider that exposes a `/models` endpoint, use Native
`provider/discover` to populate and refresh its model directory; custom model
entries remain the fallback when discovery is unavailable.

## Choosing A Wire API

Choose based on the endpoint protocol:

- Anthropic-compatible endpoint: `anthropic_messages`.
- OpenAI Responses-compatible endpoint: `openai_responses`.
- OpenAI Chat Completions-compatible endpoint: `openai_chat_completions`.

Provider names and model brand names are not enough. The wire API must match the
request format the endpoint accepts.
