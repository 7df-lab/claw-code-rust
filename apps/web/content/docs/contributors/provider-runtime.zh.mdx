本页说明 Devo 如何把规范的 provider/model 目录转换为 provider request。

## 配置输入

Runtime 读取生效后的 `providers.json` 目录：

- `crates/core/providers.json` 提供 git 跟踪的 provider template 和模型元数据；
- 用户/工作区 `providers.json` 添加或覆盖 Connection 和 model record；
- `provider.<id>.credential` 指向用户级 `auth.json` credential；
- 嵌套 model map key 就是发送给 provider 的 model id。

序列化 schema 定义在 `crates/config/src/provider/catalog.rs`。旧 TOML provider 字段只由
启动迁移解析，不是 runtime 输入。

## 解析

规范选择格式是 `provider/model` 或 `provider/model/variant`。Runtime 会校验：

- provider Connection 存在且已启用；
- model 已启用；
- 选中的 wire API 受支持；
- credential 引用能在 `auth.json` 中解析；
- 任意 request/options/headers 是有效 JSON 并且可以合并。

没有明确模型时，先使用顶层 `model`，再回退到合并目录中的第一个 enabled model。

## Router

`crates/server/src/provider_config.rs` 构建 provider runtime view。Provider crate 暴露
`ProviderRouter` trait，因此 server code 不依赖具体 provider implementation。

| Router | 用途 |
| --- | --- |
| `SingleProviderRouter` | 单个选中的 provider route。 |
| `MultiProviderRouter` | 多个 enabled provider/model route，按规范 model reference 索引。 |

选中的 route 会附加到 turn，因此即使存在多个 Connection，一个 session 仍会使用预期的
Connection。

## Wire APIs

| Config value | Provider adapter |
| --- | --- |
| `anthropic_messages` | Anthropic-compatible Messages API。 |
| `openai_chat_completions` | OpenAI-compatible Chat Completions API。 |
| `openai_responses` | OpenAI Responses-compatible API。 |

Provider-specific HTTP 和 streaming 行为属于 `devo-provider`，不属于 TUI 或 server UI 层。

## Request 默认值和 Variants

Provider、model 和 variant record 都可以有任意 `request`、`options` 和 `headers` 对象，合并
顺序从宽到窄：

1. provider；
2. model；
3. 选中的 variant。

`provider/model/variant` 选择命名 variant，但不会创建另一个 model identity。Model metadata
还包括上下文上限、能力、价格、发布状态、reasoning 支持和输入模态。

## 动态发现

Native `provider/discover` 会探测 Connection 的 `/models` 或兼容的 `/v1/models` endpoint，
规范化常见 model metadata，并将原始目录条目保存到用户 Connection 覆盖层。git 跟踪的
provider template 永远不会被修改。

## Web 能力

Web search 和 fetch 按 model override、provider override、全局 `tools` 配置的顺序解析。
可用 mode 是 `provider`、`local` 和 `disabled`。本地 search credential 仍保存在 `auth.json`。

## Validation API

Onboarding 和 provider editing 会在保存 Connection 前通过 Native `provider/validate` 进行校验。
Server 创建短生命周期 route 并尝试小型 probe request，可提前发现 endpoint、协议、credential
和 model 错误。
