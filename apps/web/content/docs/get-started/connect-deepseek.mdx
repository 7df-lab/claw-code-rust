---
title: Connect DeepSeek
description: Configure DeepSeek official API as a provider Connection.
---

DeepSeek's official API is a good first Connection for Devo. Prefer its
Anthropic-compatible path so Devo can use the provider-hosted web capabilities.

Official references:

- [DeepSeek API docs](https://api-docs.deepseek.com/)
- [Anthropic API](https://api-docs.deepseek.com/guides/anthropic_api)
- [Models and Pricing](https://api-docs.deepseek.com/quick_start/pricing)

## Create the Connection

Create an API key at the [DeepSeek Platform](https://platform.deepseek.com/api_keys),
then run:

```bash
cd /path/to/your/repo
devo onboard
```

Choose the DeepSeek provider template, review the read-only endpoint, enter the
API key, choose a model, and confirm. The recommended values are:

| Setting | Value |
| --- | --- |
| Base URL | `https://api.deepseek.com/anthropic` |
| Wire API | `anthropic_messages` |
| Model | A currently supported DeepSeek model id |

The API key is saved in user-scoped `auth.json`. `providers.json` stores only a
credential reference and the Connection's model record.

## Manual configuration

Use `<DEVO_HOME>/providers.json` for a user Connection, or
`<workspace>/.devo/providers.json` for a workspace overlay:

```json
{
  "model": "deepseek/deepseek-v4-flash",
  "small_model": "deepseek/deepseek-v4-flash",
  "provider": {
    "deepseek": {
      "name": "DeepSeek Anthropic",
      "base_url": "https://api.deepseek.com/anthropic",
      "credential": "deepseek_api_key",
      "wire_api": "anthropic_messages",
      "web_search": {"mode": "provider"},
      "web_fetch": {"mode": "provider"},
      "models": {
        "deepseek-v4-pro": {
          "name": "DeepSeek V4 Pro",
          "default_reasoning_effort": "high"
        },
        "deepseek-v4-flash": {
          "name": "DeepSeek V4 Flash",
          "default_reasoning_effort": "high"
        }
      }
    }
  }
}
```

Store the secret separately in `<DEVO_HOME>/auth.json`:

```json
{
  "version": 1,
  "credentials": {
    "deepseek_api_key": {
      "kind": "api_key",
      "value": "sk-your-deepseek-api-key"
    }
  }
}
```

The provider map key (`deepseek`) and nested model map key form the stable
`provider/model` identity. There is no separate binding, slug, request-model,
or description field.

## OpenAI-compatible alternative

If you specifically need DeepSeek's OpenAI Chat Completions format, create a
separate Connection overlay with:

```json
{
  "model": "deepseek-openai/deepseek-v4-flash",
  "provider": {
    "deepseek-openai": {
      "name": "DeepSeek OpenAI Compatible",
      "base_url": "https://api.deepseek.com",
      "credential": "deepseek_api_key",
      "wire_api": "openai_chat_completions",
      "models": {
        "deepseek-v4-flash": {"name": "DeepSeek V4 Flash"}
      }
    }
  }
}
```

## Verify

Run:

```bash
devo doctor
devo
```

If it fails, check that the credential id matches `auth.json`, the base URL
matches the wire API, and the nested model id is currently supported by
DeepSeek. Disconnect and reconnect the Connection from `devo onboard` when you
need to replace its endpoint or credential.
