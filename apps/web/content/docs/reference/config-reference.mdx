This page lists the main config files and fields. For guided setup, start with
[Config Basics](../configuration/config-basics), [Provider Setup](../configuration/provider-setup),
and [Provider and Model Configuration](../configuration/model-bindings).

## Files

| File | Purpose |
| --- | --- |
| `<DEVO_HOME>/config.toml` | User-level Devo config. |
| `<DEVO_HOME>/providers.json` | User-level provider connections, model directory, and active model. |
| `<DEVO_HOME>/auth.json` | User-level secrets and credentials. |
| `<workspace>/.devo/config.toml` | Workspace-level config overlay. |
| `<workspace>/.devo/providers.json` | Workspace-level provider/model overlay. |

Default `DEVO_HOME` paths:

| Platform | Default |
| --- | --- |
| macOS/Linux | `~/.devo` |
| Windows | `C:/Users/your-username/.devo` |

If `DEVO_HOME` is set, it must point to an existing directory.

## Precedence

Effective config is resolved in this order, highest priority first:

1. command-line startup arguments;
2. `<workspace>/.devo/providers.json` for provider/model fields;
3. `<workspace>/.devo/config.toml` for application fields;
4. `<DEVO_HOME>/providers.json` for provider/model fields;
5. `<DEVO_HOME>/config.toml` for application fields;
6. built-in defaults and the tracked provider/model directory.

Provider API keys are stored in the user-scoped `auth.json`. The provider record
in `providers.json` stores only the matching `provider.<id>.credential` reference;
neither file containing a real secret should be committed to a repository.
The built-in provider/model directory is the git-tracked
`crates/core/providers.json` asset.

## Top-Level Fields

| Field | Type | Meaning |
| --- | --- | --- |
| `summary_model` | enum | Selects the model used for context summaries. |
| `server` | table | Server runtime defaults. |
| `logging` | table | Diagnostic logging behavior. |
| `skills` | table | Skill discovery roots and behavior. |
| `experimental` | table | Experimental feature gates. |
| `mcp_oauth_credentials_store` | `auto`, `keyring`, `file` | Storage backend for MCP OAuth credentials. |
| `mcp` | table | MCP server discovery and runtime config. |
| `tools` | table | Tool-specific runtime config. |
| `hooks` | table | External lifecycle hooks. |
| `provider_http` | table | Shared provider HTTP transport settings. |
| `updates` | table | Startup update-check defaults. |
| `project_root_markers` | string array | Markers used to discover project root for instructions. Defaults to `.git`. |
| `projects` | table | User-level settings remembered per project key. |

Provider-related fields are stored in `providers.json`:

| Field | Meaning |
| --- | --- |
| `model` | Active model reference in `provider/model` form. |
| `small_model` | Optional lower-cost model for lightweight background tasks such as session-title generation; when unset, Devo auto-selects a same-provider lightweight model and then falls back to `model`. |
| `reasoning_effort` | User-facing reasoning effort selection. |
| `provider.<id>` | Provider connection and model directory entry. |
| `provider.<id>.models.<model-id>` | Optional model metadata and request defaults. |

The provider id and nested model id are the identity. Users do not need a
separate binding id, model slug, request model, or model description. The old
TOML provider fields remain readable only for migration.

## `[provider_http]`

| Field | Type | Meaning |
| --- | --- | --- |
| `proxy_url` | string | Optional proxy URL for provider requests, local web fetch/search, and code search model downloads. Supports `http://`, `https://`, `socks5://`, and `socks5h://`. |
| `no_proxy` | string | Optional comma-separated host bypass list, such as `localhost,127.0.0.1,::1`. |

Desktop Server network proxy settings override these values only inside the
Desktop-managed runtime process. They do not modify `config.toml`.

## `[server]`

| Field | Type | Meaning |
| --- | --- | --- |
| `listen` | string array | Server listen endpoints. |
| `max_connections` | integer | Maximum concurrent client connections. Defaults to `32`. |
| `event_buffer_size` | integer | Event buffer capacity per connection. Defaults to `1024`. |
| `idle_session_timeout_secs` | integer | Idle session timeout in seconds. Defaults to `1800`. |
| `persist_ephemeral_sessions` | bool | Whether ephemeral sessions are persisted. Defaults to `false`. |

### `[server.auth]`

| Field | Type | Meaning |
| --- | --- | --- |
| `enabled` | bool | Requires server authentication before non-initialization server methods. Defaults to `false`. |
| `method_id` | string | Server authentication method id advertised during initialization. Defaults to `agent-login`. |
| `name` | string | Human-readable authentication method name. Defaults to `Agent login`. |
| `description` | string | Optional authentication method description. |
| `logout` | bool | Advertises and supports ACP `logout` when auth is enabled. Defaults to `true`. |

When enabled, auth state is per connection and gates both ACP methods and legacy
Devo server methods.

## `providers.json`

| Field | Type | Meaning |
| --- | --- | --- |
| `model` | string | Active model reference, for example `openai/gpt-5.5`. |
| `small_model` | string | Optional lower-cost model for lightweight background tasks; invalid or absent values use same-provider automatic selection, then `model`. |
| `reasoning_effort` | string | Global logical reasoning selection. |
| `provider` | object | Provider records keyed by provider id. |

Provider record fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `name` | string | Optional human-readable provider name. |
| `enabled` | bool | Whether the provider can be used. Defaults to `true`. |
| `base_url` | string | Provider endpoint. |
| `credential` | string | Credential id resolved from the user-scoped `auth.json`. |
| `headers` | object | Extra HTTP headers for provider requests. |
| `options` | object | Arbitrary adapter/SDK options. |
| `request` | object | Arbitrary provider-level request-body defaults. |
| `wire_api` | string | Provider wire API default. |
| `env` | string array | Environment variable names exposed to integrations. |
| `models` | object | Model records keyed by provider-facing model id. |

Supported wire API values:

- `anthropic_messages`
- `openai_chat_completions`
- `openai_responses`

Provider responses do not have an application-level response timeout. Slow local
models may take as long as needed to load or generate output; users can cancel a
request at any time. Connection establishment retains an internal deadline.

| --- | --- | --- |

| `wire_api` | string | Optional wire API override. |
| `context_window` | integer | Maximum context window in tokens. |
| `effective_context_window_percent` | number | Usable percentage of the context window (may be fractional). |
| `max_tokens` | integer | Default response-output limit. |
| `reasoning_capability` | object/string | Reasoning controls exposed by the model. |

| `input_modalities` | string array | Accepted input types, such as `text` and `image`. |
| `temperature`, `top_p`, `top_k` | number | Optional sampling defaults. |
| `family`, `release_date`, `status`, `channel` | string | Optional catalog metadata. |
| `capabilities`, `cost`, `metadata` | object | Open-ended model metadata preserved by the catalog. |
| `base_instructions` | string | Optional model-specific system instructions. |
| `truncation_policy` | object | `{"mode":"bytes"|"tokens","limit":8000}`. |
| `options`, `request` | object | Arbitrary adapter options and request-body defaults. |
| `headers` | object | Model-specific headers layered over provider headers. |
| `variants` | object | Named variant records with request/options/headers overrides. |
| `default_variant` | string | Variant selected when none is specified. |
| `web_search`, `web_fetch` | object | Optional provider-hosted capability overrides. |

## `auth.json`

`auth.json` stores user-scoped provider credentials. Provider configurations use
the matching `provider.<id>.credential` reference in `providers.json`:

```json
{
  "provider": {
    "deepseek": {
      "credential": "deepseek_api_key"
    }
  }
}
```

The actual secret belongs in `auth.json`:

```json
{
  "version": 1,
  "credentials": {
    "deepseek_api_key": {
      "kind": "api_key",
      "value": "sk-your-key"
    }
  }
}
```

Credential fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `version` | integer | Credential file schema version. Current value is `1`. |
| `credentials.<id>.kind` | `api_key` | Credential kind. |
| `credentials.<id>.value` | string | Secret value. |

The credential id must match in both files. `apiKey` and `api_key` are not
canonical fields in `providers.json` and are not resolved. Do not commit
`auth.json` when it contains a real secret.

## Update Checks

The default update config enables startup checks with a 24-hour minimum
interval:

```toml
[updates]
enabled = true
check_on_startup = true
check_interval_hours = 24
```

Disable startup checks in environments that require fully offline operation.
