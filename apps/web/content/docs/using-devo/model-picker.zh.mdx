---
title: Model Picker
description: 在已配置的 provider/model selection 之间切换。
---

使用 `/model` 切换当前 session 的 active model。

```text
/model
```

Picker 会在底部 pane 打开，并替换 composer 输入区域：

- `Up` / `Down`（或 `j` / `k`）在模型列表中移动
- `Left` / `Right` 在当前聚焦模型支持的推理强度选项间切换
- `Enter` 一次应用聚焦的模型与所选推理强度
- `Esc` 关闭且不修改模型

当配置的 model 较多时，模型列表最多显示 8 行，并滚动以保持聚焦行可见。

## Picker 显示什么

Picker 来自配置的 `provider/model` selection。每个条目显示 display name，并在可用时在右侧显示 provider hint。

当前模型会在列表中标记。如果 model record 有 display name，Devo 使用它；否则回退到 catalog label 或原始 model reference。

## 直接选择

也可以直接传入 `provider/model` reference：

```text
/model gpt-5-codex
```

当参数匹配已配置 model 时，Devo 会从目录解析它的 Connection、provider-facing model id、wire API 和 display name。`provider/model/variant` 还可以同时选择指定的 variant。

## Reasoning Effort

某些模型暴露 configurable reasoning effort。对这些模型，picker 在模型列表下方显示横向推理强度选项。切换聚焦模型时会更新可用选项；若先前选中的强度仍被支持则保留，否则回退到该模型的默认值。

若聚焦模型没有暴露选项，强度行会隐藏，`Enter` 只应用模型。

确认后，Devo 更新 header，并把 model 和 reasoning effort selection 作为 turn context 发送给 runtime。

## Session Scope

`/model` 修改 active session context。它不会改写 provider 配置文件。

添加新的 provider Connection 或 model：

```bash
devo onboard
```

如果希望某个 model 成为启动默认值，应更新 `providers.json`，而不是依赖 session 内的 `/model` 切换。

## Devo 工作中

Devo 生成任务时会阻止模型切换。如果在 running turn 中尝试切换模型，transcript 会提示生成期间无法修改 model。

等待当前 turn 完成，用 `Esc` 中断，或开始新 session 后再切换。
